    Kapitel 2

    Viele Punkte auf einmal

    Unser Netz rechnet bisher Punkt für Punkt. In diesem Kapitel schreiben wir dieselbe Rechnung für alle Punkte auf einmal, mit Matrizen, und sehen, wie Scaly die vielen Zahlen hält und schnell verrechnet.

    Eine Zeile je Punkt

    Ein Neuron bildet für einen Punkt seine gewichtete Summe z=w1x+w2y+b. Für die 200 Trainingspunkte des Kreises sind das 200 Summen, und eine Schicht aus vier Neuronen bildet 800. Schreiben wir die Eingaben aller Punkte untereinander, eine Zeile je Punkt, entsteht eine Tabelle aus 200 Zeilen und 2 Spalten, eine Matrix X. Die Gewichte der Schicht schreiben wir ebenso als Matrix W, eine Spalte je Neuron, also 2 Zeilen und 4 Spalten.

    Die Summe von Neuron j für Punkt i ist dann Zeile i von X mit Spalte j von W, Zahl für Zahl multipliziert und zusammengezählt, dazu der Bias des Neurons:

    zij=xi1w1j+xi2w2j+bj

    Alle diese Summen zusammen sind wieder eine Matrix Z, eine Zeile je Punkt und eine Spalte je Neuron. Die Rechnung, die sie aus X und W bildet, heißt Matrixprodukt und wird geschrieben wie eine Multiplikation:

    Z=XW+bH=tanh⁡(Z)

    Den Bias zählen wir dabei zu jeder Zeile, und tanh wirkt auf jede Zahl für sich. Jede weitere Schicht ist dieselbe Zeile noch einmal, mit H statt X als Eingabe. Die ganze Vorwärtsrechnung unseres Netzes sind drei solche Zeilen.

    Ausprobieren

    Sieh dir das Matrixprodukt als Animation an. Für ein kleines Beispiel, X mit drei Zeilen, W mit drei Spalten, entsteht dort eine Zahl von Z nach der anderen: Zeile i und Spalte j leuchten auf, dann die beiden Paare von Zahlen, die miteinander malgenommen werden, und darunter läuft die Rechnung mit. Mit Ein Schritt kannst du in Ruhe mitrechnen.

    Was gewinnen wir dadurch? Gerechnet wird genau dasselbe: dieselben Multiplikationen und Additionen in derselben Reihenfolge, und das Programm dieses Kapitels kommt Zahl für Zahl auf das Ergebnis des Spielfelds. Gewonnen ist dreierlei. Das Programm wird klarer: Die Vorwärtsrechnung sind drei Zeilen, und die Zahl der Punkte kommt in ihnen nicht mehr vor. Das Matrixprodukt ist die eine Rechnung, für die Prozessoren und Grafikkarten gebaut sind; große Matrizen verteilen sich gut auf die Kerne und auf die Karte. Bei unseren 200 Punkten und vier Neuronen ist davon noch nichts zu merken, die Matrizen sind winzig. Und es bereitet das nächste Kapitel vor: Ein Programm, das Ableitungen selbst bildet, braucht dann eine Regel für eine Handvoll Matrixoperationen statt für jede einzelne Multiplikation.

    Backpropagation mit Matrizen

    Rückwärts geht es genauso. In Kapitel 1 hatte jedes Neuron für jeden Punkt seinen Anteil am Fehler, den Fehler nach seiner Summe. Schreiben wir auch diese Anteile untereinander, eine Zeile je Punkt und eine Spalte je Neuron, entsteht eine Matrix D, so groß wie Z: dij ist der Anteil von Neuron j am Fehler für Punkt i. Für die Ausgabe ist das eine einzige Spalte, Zeile für Zeile das bekannte (a−t)(1−a2).

    Eine Schicht weiter vorn bekommt Neuron k seinen Anteil über alle Gewichte, mit denen die Neuronen der Schicht dahinter seine Antwort lesen, und durch sein eigenes tanh:

    d′ik=(∑jdijwkj)(1−hik2)

    Bei einer einzigen Ausgabe hat die Summe einen Summanden, und das ist das dvj aus Kapitel 1. Die Summe selbst ist wieder ein Matrixprodukt: Zeile i von D mit Zeile k von W. Damit daraus Zeile mal Spalte wird, wird W gespiegelt, seine Zeilen werden Spalten; das heißt die Transponierte WT. Das tanh wirkt auf jede Zahl für sich, Zahl mal Zahl an derselben Stelle, geschrieben ⊙:

    D′=(DWT)⊙(1−H2)

    Bleiben die Ableitungen der Gewichte. In Kapitel 1 trug jeder Punkt zum Gewicht vj das Produkt dhj bei: die Antwort, die das Gewicht liest, mal den Anteil des Neurons, das sie liest. Über alle Punkte zusammengezählt und durch ihre Anzahl geteilt, war das die Ableitung. Für wkj ist es genauso, Punkt i trägt hikdij bei, und die Summe über alle Punkte ist Zeile k von HT mal Spalte j von D:

    ∑ihikdij=(HTD)kj

    Alle diese Summen zusammen sind das Matrixprodukt HTD, so groß wie W, eine Zahl für jedes Gewicht. Der Bias liest statt einer Antwort immer 1, seine Summen sind darum einfach die Spaltensummen von D. Damit ist ein ganzer Lernschritt in Matrizen geschrieben: vorwärts für jede Schicht ihr Z und H, rückwärts für jede Schicht ihr D, daraus HTD und die Spaltensummen, und dann wird jedes Gewicht wie bisher um seine Ableitung verringert, geteilt durch die Anzahl der Punkte und mal die Lernrate.

    Im Programm dieses Kapitels ist jede dieser Formeln eine Funktion. back bildet aus dem D einer Schicht, ihren Gewichten W und den Antworten H der Schicht davor deren D′:

    function back(d: Matrix, w: Matrix, h: Matrix) returns Matrix
{
    var below zeros(d.rows, w.rows)
    for i in d.rows
    {
        var k 0
        while k < w.rows
        {
            var s 0.0
            var j 0
            while j < w.cols
            {
                s := s + d.at(i, j) * w.at(k, j)
                j := j + 1
            }
            let out h.at(i, k)
            below.put(i, k, s * (1.0 - out * out))
            k := k + 1
        }
    }
    below
}

    Die äußere Schleife geht über die Punkte i, die mittlere über die Neuronen k der Schicht davor, die innere bildet die Summe über j. Sie liest dabei Zeile k von W, und das ist Spalte k von WT: Die Transponierte wird nie hingeschrieben, es genügt, W andersherum zu lesen. Und das ⊙ ist das Malnehmen in below.put, jede Summe mal die Steigung ihres eigenen tanh.

    weight_grad ist das Matrixprodukt HTD nach demselben Muster; auch HT wird nicht hingeschrieben, die innere Schleife liest Spalte k von H. bias_grad zählt die Spalten von D zusammen, out_share bildet das D der Ausgabe, und descend verringert jede Zahl einer Matrix um ihre Ableitung. Damit ist der ganze Lernschritt:

    procedure step(mutable net: Net, x: Matrix, t: Matrix, rate: f64)
{
    ; forward, layer by layer
    let h1 layer(x, net.w1, net.b1)
    let h2 layer(h1, net.w2, net.b2)
    let a layer(h2, net.w3, net.b3)
    ; backward, layer by layer
    let d3 out_share(a, t)
    let d2 back(d3, net.w3, h2)
    let d1 back(d2, net.w2, h1)
    ; every weight a little against its gradient
    descend(net.w3, weight_grad(h2, d3), rate, x.rows)
    descend(net.b3, bias_grad(d3), rate, x.rows)
    descend(net.w2, weight_grad(h1, d2), rate, x.rows)
    descend(net.b2, bias_grad(d2), rate, x.rows)
    descend(net.w1, weight_grad(x, d1), rate, x.rows)
    descend(net.b1, bias_grad(d1), rate, x.rows)
}

    Oben die drei Zeilen vorwärts, darunter die drei rückwärts, von der Ausgabe zur Eingabe, denn jedes D entsteht aus dem D der Schicht dahinter. Erst wenn alle D da sind, ändern sich die Gewichte: back braucht die alten. Die Punkte kommen in diesen Zeilen nur noch als x.rows vor, ihre Anzahl, durch die descend teilt. Das ganze Programm steht auf GitHub.

    Wo die Zahlen liegen

    Eine Matrix ist im Programm ein Record aus ihren beiden Größen und einem Vector[f64] mit ihren Zahlen, Zeile für Zeile hintereinander. Zeilen und Spalten zählen dort von 0 an, und die Zahl in Zeile i und Spalte j steht an Stelle i·n+j, wenn die Matrix n Spalten hat:

    define Matrix(rows: int, cols: int, data: Vector[f64])
{
    function at(this, i: int, j: int) returns f64
        this.data[i * this.cols + j]

    procedure put(mutable this, i: int, j: int, v: f64)
        this.data.put(i * this.cols + j, v)
}

function zeros(rows: int, cols: int) returns Matrix
{
    var data Vector[f64]#(rows * cols)
    for k in rows * cols
        data.put(k, 0.0)
    Matrix(rows, cols, data)
}

    zeros legt eine Matrix an, in der jede Zahl 0 ist. Das # hinter dem Typ sagt, wo ihre Zahlen liegen; dazu gleich.

    Ein Lernschritt legt eine ganze Reihe solcher Matrizen an: vorwärts die Antworten der drei Schichten, rückwärts die drei D, dazu die Ableitungen der Gewichte. Zusammen sind das gut 2800 Zahlen oder 22 KB je Schritt, für 50 000 Schritte 1,1 GB. Gebraucht wird davon immer nur ein Schritt: Sind die Gewichte verändert, ist alles andere überholt.

    Andere Sprachen räumen solche Zwischenwerte mit einem Garbage Collector weg, der von Zeit zu Zeit nachsieht, was das Programm noch erreicht; in C gibt man jeden einzeln mit free zurück. Scaly tut keins von beiden. Was ein Aufruf anlegt, liegt auf einer Speicherseite dieses Aufrufs, und kehrt er zurück, wird die ganze Seite auf einmal frei. Was er zurückgibt, muss das überleben, und das legt er darum gleich auf der Seite seines Aufrufers an. Das ist das # in zeros. Dass layer, back und die anderen Funktionen ihr Ergebnis aus zeros zurückgeben, sieht der Compiler selbst und reicht die Seite weiter. So liegen alle Matrizen eines Lernschritts auf der Seite von step, und die wird frei, wenn step zurückkehrt. Nur die Gewichte bleiben: Sie hat das Hauptprogramm angelegt, und descend schreibt in sie hinein.

    Gemessen braucht das Programm mit 500 Schritten höchstens 2,08 MB Speicher und mit 50 000 Schritten genauso viel. Die Lernschritte kommen und gehen, der Speicher wächst nicht mit.

    Eine Falle gibt es dabei. Auch das Hauptprogramm hat eine Seite, und die lebt bis zum Ende. Schreibt man die Ausgabe der Fehler direkt in die Hauptschleife, liegen die Antworten, die sie dafür berechnet, auf dieser Seite und bleiben: Nach 50 000 Schritten, mit einer Ausgabe alle 100 Schritte, sind es 18,7 MB. Darum ist die Ausgabe eine Prozedur für sich, und was in ihr entsteht, geht mit ihr:

    procedure report(step: int, net: Net, x: Matrix, t: Matrix,
                 tx: Matrix, tt: Matrix)
{
    let train loss(answer(net, x), t)
    let test loss(answer(net, tx), tt)
    print "step `step` train `train` test `test`"
}
