    Kapitel 4

    Das Band

    In Kapitel 3 haben wir jede Ableitung von Hand hergeleitet und für jede eine Funktion geschrieben. In diesem Kapitel bildet das Programm sie selbst: Wir schreiben nur noch die Vorwärtsrechnung, so wie die Formeln, und der Weg zurück ergibt sich aus ihr.

    Werte, die sich ihre Herkunft merken

    Die Rückwärtsrechnung aus Kapitel 3 folgt einem Muster. Zu jedem Schritt vorwärts gehört ein Schritt rückwärts, und welcher, hängt nur davon ab, was vorwärts gerechnet wurde: ein Matrixprodukt, eine Summe, ein tanh. Merkt sich jeder Wert, wie er entstanden ist, kann ein Programm diesen Weg rückwärts gehen, ohne dass wir ihn hinschreiben. Das heißt automatisches Differenzieren, und die Aufzeichnung, die es dabei abschreitet, heißt das Band.

    In unserem Programm hat jeder Wert dafür einen Eintrag:

    define Entry(kind: int, a: ref[Entry]?, b: ref[Entry]?, value: Matrix,
             var grad: Matrix, var seen: bool)

    kind sagt, was gerechnet wurde, a und b sind die Einträge, aus denen der Wert entstand, und value ist der Wert selbst, eine Matrix. Das Fragezeichen hinter ref[Entry] heißt, dass ein Verweis fehlen darf: Ein tanh hat nur ein a, die Punkte und die Gewichte, mit denen die Rechnung beginnt, haben keins. grad ist so groß wie value und nimmt auf dem Weg zurück die Ableitungen auf; seen brauchen wir dort auch.

    Für eine Matrix A schreiben wir diese Ableitungen als Matrix GA, gleich groß:

    (GA)ij=∂L/∂aij

    Die Zahl an Stelle i, j sagt, wie stark sich der Fehler L ändert, wenn sich aij ein wenig ändert. Das D aus Kapitel 3 ist so eine Matrix, das GZ einer Schicht.

    Ein Wert der Rechnung ist ein Verweis auf seinen Eintrag, und für Werte schreiben wir die Operatoren * und + selbst:

    define Value(at: ref[Entry])
{
    operator *(this, other: Value) returns Value
    {
        let m product(this.at.value, other.at.value)
        Value(&# Entry(TIMES, this.at, other.at, m, zeros(m.rows, m.cols), false))
    }

    operator +(this, other: Value) returns Value
    {
        let m plus(this.at.value, other.at.value)
        Value(&# Entry(PLUS, this.at, other.at, m, zeros(m.rows, m.cols), false))
    }
}

    Jeder rechnet mit den Matrizen seiner beiden Werte, mit product, dem Matrixprodukt, und mit plus, das eine Zeile wie den Bias zu jeder Zeile zählt. Für das Ergebnis legt er einen neuen Eintrag an, der auf die beiden zeigt. Matrizen, mit denen die Rechnung beginnt, macht leaf zu Werten, und tanh ist eine Funktion, die wie die Operatoren einen Eintrag anlegt:

    function leaf(m: Matrix) returns Value
    Value(&# Entry(LEAF, null, null, m, zeros(m.rows, m.cols), false))

function tanh(x: Value) returns Value
{
    let m apply_tanh(x.at.value)
    Value(&# Entry(TANH, x.at, null, m, zeros(m.rows, m.cols), false))
}

    Damit schreibt sich eine Schicht so wie ihre Formeln Z=XW+b und H=tanh⁡(Z), in einer Zeile: tanh(leaf(X) * w1 + b1).

    Bibliotheken wie PyTorch führen das Band als Liste: Jede Rechnung hängt sich an, während sie läuft. In Scaly geht das nicht so. Operatoren und Funktionen sind rein, sie geben ihr Ergebnis zurück und ändern sonst nichts, auch keine Liste außerhalb. Darum zeigt hier jeder Eintrag auf die, aus denen er entstand. Zusammen bilden die Einträge einen Graphen, der vom Fehler bis zu den Punkten und Gewichten reicht, und die Reihenfolge, das eigentliche Band, bildet erst der Weg zurück aus ihm.

    Bleibt die Frage, wo die Einträge liegen. &# Entry(…) legt einen Eintrag an und gibt mit & einen Verweis darauf. Das # sagt wie in zeros, wo: auf der Seite des Aufrufers. Aufgerufen werden die Operatoren und tanh in step, also liegen alle Einträge eines Lernschritts auf dessen Seite und gehen mit ihr, wie die Matrizen in Kapitel 3. Kopiert wird dabei keine Zahl: Eine Matrix weiterzugeben gibt ihre Größen und den Verweis auf ihre Zahlen weiter, und so sieht der Eintrag, den leaf(net.W1) anlegt, dieselben Zahlen wie das Netz.

    Der Weg zurück

    Am Ende der Vorwärtsrechnung steht der Fehler L, eine Matrix mit einer einzigen Zahl, und seine Ableitung nach sich selbst ist 1. Von dort geht es zurück: Jeder Eintrag reicht seine Ableitungen an die Einträge weiter, aus denen er entstand. Das darf er erst, wenn alle Einträge, die ihn lesen, ihm ihren Teil schon gegeben haben. order bringt die Einträge dafür in eine Reihenfolge, jeden nach denen, aus denen er entstand, und backward geht sie von hinten nach vorn ab:

    procedure order(mutable e: ref[Entry], mutable tape: Array[ref[Entry]])
{
    if e.seen
        return
    e.seen := true
    let a e.a
    if a <> null
        order(a, tape)
    let b e.b
    if b <> null
        order(b, tape)
    tape.add(e)
}

procedure backward(mutable loss: Value)
{
    var tape Array[ref[Entry]]()
    order(loss.at, tape)
    loss.at.grad.put(0, 0, 1.0)
    var k tape.length
    while k > 0
    {
        k := k - 1
        back(tape[k])
    }
}

    order geht zuerst zu a und b und hängt den Eintrag selbst erst danach an. seen sorgt dafür, dass ein Eintrag, den zwei Rechnungen lesen, nur einmal aufs Band kommt. In unserem Netz liest jeden Wert nur eine Rechnung, aber so stimmt backward für jede.

    Was ein Eintrag weiterreicht, hängt nur von seiner Art ab. Für das Matrixprodukt:

    C=ABGA=GCBT,GB=ATGC

    Das sind die beiden Produkte aus Kapitel 3: GCBT ist das DWT, das den Fehler eine Schicht nach vorn reicht, und ATGC ist das HTD, die Ableitung der Gewichte. Die Summe C=A+b reicht GC unverändert weiter, an A und an b; weil b zu jeder Zeile gezählt wurde, bekommt es die Spaltensummen, wie der Bias in Kapitel 3. Für tanh wird jede Zahl mit der Steigung an ihrer Stelle malgenommen:

    H=tanh⁡(Z)GZ=GH⊙(1−H2)

    Und für den Fehler, den Mittelwert über die n Punkte:

    L=1n∑i12(ai−ti)2∂L/∂ai=(ai−ti)/n

    Hintereinander ergeben diese Regeln die Formeln aus Kapitel 3. Der Fehler reicht (a−t)/n an die Antwort des Netzes, ihr tanh macht daraus (a−t)(1−a2)/n, das D der Ausgabe, hier schon durch die Zahl der Punkte geteilt. Die Summe reicht es an das Produkt und an b3 weiter, das Produkt an h2 und an w3, und so fort bis zu den Punkten.

    Lesen zwei Rechnungen denselben Wert, kommen bei seinem Eintrag zwei Ableitungen an, und sie zählen sich zusammen. Darum zählen die Regeln im Programm zu grad dazu, statt es zu setzen. back wählt die Regel nach der Art des Eintrags:

    procedure back(mutable e: ref[Entry])
{
    let a e.a
    if a = null
        return
    if e.kind = TANH
        back_tanh(e.value, e.grad, a)
    let b e.b
    if b = null
        return
    if e.kind = TIMES
        back_times(e.grad, a, b)
    if e.kind = PLUS
        back_plus(e.grad, a, b)
    if e.kind = LOSS
        back_loss(e.grad, a, b)
}

    Jede Regel ist eine kleine Prozedur. Die für tanh:

    procedure back_tanh(H: Matrix, G: Matrix, mutable a: ref[Entry])
{
    for k in H.rows * H.cols
    {
        let h H.data[k]
        a.grad.data.put(k, a.grad.data[k] + G.data[k] * (1.0 - h * h))
    }
}

    Und das ist der ganze Lernschritt:

    procedure step(mutable net: Net, X: Matrix, T: Matrix, rate: f64)
{
    let w1 leaf(net.W1)
    let b1 leaf(net.b1)
    let w2 leaf(net.W2)
    let b2 leaf(net.b2)
    let w3 leaf(net.W3)
    let b3 leaf(net.b3)
    let h1 tanh(leaf(X) * w1 + b1)
    let h2 tanh(h1 * w2 + b2)
    let a tanh(h2 * w3 + b3)
    var l loss(a, leaf(T))
    backward(l)
    descend(net.W1, w1, rate)
    descend(net.b1, b1, rate)
    descend(net.W2, w2, rate)
    descend(net.b2, b2, rate)
    descend(net.W3, w3, rate)
    descend(net.b3, b3, rate)
}

    Die drei Zeilen vorwärts stehen da wie die Formeln, und die Rückwärtsrechnung, in Kapitel 3 drei Zeilen und vier Funktionen, ist ein Aufruf von backward. Danach steht im Eintrag jedes Gewichts seine Ableitung, und descend verringert das Gewicht um sie, mal die Lernrate. Ein anderes Netz, mit einer Schicht mehr oder einer anderen Aktivierung, braucht keine neue Rückwärtsrechnung, nur für jede neue Art von Rechnung ihre Regel; der letzte Abschnitt probiert das aus. Das ganze Programm steht auf GitHub.

    Dieselben Zahlen

    Rechnet das Band richtig? Das Programm dieses Kapitels lernt den Kreis aus denselben Startgewichten und mit derselben Lernrate wie das aus Kapitel 3, also muss es dieselben Fehler ausgeben. Fast alle Zahlen stimmen Ziffer für Ziffer, drei weichen ab:

    SchrittKapitel 3Band
    100, Training0.483253082286431430.48325308228643155
    300, Test0.398500796376129840.3985007963761298
    500, Training0.19223560940857510.19223560940857506

    Die Abweichung steht in der 16. oder 17. Stelle, und mit dem Band hat sie nichts zu tun: Das Programm rechnet in einer anderen Reihenfolge. Kapitel 3 beginnt jede Summe mit dem Bias, das Band zählt ihn zuletzt dazu. Kapitel 3 teilt die fertige Ableitung durch die Zahl der Punkte, das Band teilt jeden Anteil, bevor es ihn dazuzählt. Mathematisch ist das gleich, aber eine Kommazahl hat nur 53 Binärstellen, und jede Rechnung rundet auf sie. In anderer Reihenfolge wird an anderen Stellen gerundet. Am Ergebnis ändert das nichts: Beide Programme raten 188 der 200 Testpunkte richtig.

    Ganz umsonst ist das Band nicht. Es legt für jeden Wert eine zweite Matrix an, und es bildet auch Ableitungen, die niemand braucht, die nach den Punkten. Für 50 000 Lernschritte braucht es 1,65 Sekunden statt 1,02, beide mit scaly build --release gebaut, auf demselben M1 Pro. Der Speicher wächst trotzdem nicht: höchstens 2,06 MB, bei 500 Schritten wie bei 50 000, denn die Einträge gehen mit der Seite von step.

    Eine andere Aktivierung

    Was bringt das Band, wenn es dieselben Zahlen langsamer ausrechnet? Es zahlt sich aus, sobald sich das Netz ändert. Nehmen wir in den beiden verborgenen Schichten statt tanh die Aktivierung, die Kapitel 2 für große Netze erwähnt hat, ReLU:

    H=max⁡(0,Z)

    Die Ausgabe bleibt tanh, sie soll weiter zwischen −1 und 1 antworten. Mit dem Band braucht ReLU dasselbe wie tanh: eine Funktion, die einen Eintrag anlegt, und eine Regel für den Weg zurück.

    function relu(x: Value) returns Value
{
    let m apply_relu(x.at.value)
    Value(&# Entry(RELU, x.at, null, m, zeros(m.rows, m.cols), false))
}

    apply_relu setzt jede negative Zahl auf 0. Die Steigung von ReLU ist 1, wo die Summe positiv ist, und sonst 0. Die Regel reicht GH also dort unverändert weiter, wo zij>0 ist, und sonst nichts. Ob die Summe positiv war, sieht sie an der Antwort, denn ReLU gibt genau dort mehr als 0:

    procedure back_relu(H: Matrix, G: Matrix, mutable a: ref[Entry])
{
    for k in H.rows * H.cols
    {
        if H.data[k] > 0.0
            a.grad.data.put(k, a.grad.data[k] + G.data[k])
    }
}

    Dazu kommt eine Zeile in back, die diese Regel für die Art RELU aufruft, und im Lernschritt wird an zwei Stellen aus tanh ein relu: relu(leaf(X) * w1 + b1). Das ist alles.

    Ohne Band wäre mehr zu überlegen. In Kapitel 3 steckt die Steigung von tanh an zwei Stellen der hergeleiteten Rückwärtsrechnung: als 1−h2 in back, für die verborgenen Schichten, und in out_share, für die Ausgabe. Wir müssten wissen, welche davon zur Steigung von ReLU wird und welche bleibt, und für eine Operation, die nicht einfach Zahl für Zahl wirkt, die Kette neu herleiten. Mit dem Band bleibt jede Regel bei ihrer Operation, und wie die Regeln sich verketten, ergibt sich aus dem Netz.

    Ob die neue Regel stimmt, lässt sich am Spielfeld aus Kapitel 2 prüfen: Sein Programm kann ReLU auch, mit einer Rückwärtsrechnung von Hand. Aus denselben Startgewichten druckt das Programm dieses Abschnitts dieselben Fehler wie das Spielfeld, wieder bis auf die letzten Stellen.

    Dabei zeigt sich, dass ReLU hier anders lernt. Nach 500 Schritten stimmen erst 132 der 200 Testpunkte, nach 2000 Schritten 157, und der Fehler sinkt in dieser Zeit nur von 0,51 auf 0,33. Dann geht es schnell: Nach 2500 Schritten stimmen alle 200. Mit tanh war das schon nach 1000 Schritten so. Welche Aktivierung besser ist, hängt vom Netz und von den Daten ab, und ausprobieren lässt es sich jetzt mit einem Wort. Das Programm mit ReLU steht auf GitHub.
