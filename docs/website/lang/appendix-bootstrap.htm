    Appendix C

    Bootstrap History and the Seed

    Scaly is self-hosted, and the committed seed — the compiler emitted as its own textual LLVM IR under seed/ — is the sole bootstrap root. The normal way to build the compiler is from that seed — it is what the installer of Installing Scaly does on your machine; it needs only LLVM 21 and a C compiler. A single seed covers every 64-bit little-endian target, Windows included, and the release workflow builds the programs from it natively on macOS, Linux and Windows, on both x86-64 and AArch64.

    The seed is refreshed by tools/seed.sh: it bootstraps a compiler from the committed seed, re-emits the compiler sources with it, and verifies the fixed point — the seed must reproduce itself byte-identically — before tools/install-seed.sh installs the new files. Textual IR is diffable and auditable, which is why Scaly ships it instead of opaque per-platform binaries. See RELEASING.md in the repository for the full seed-distribution checklist.

    Historically, the self-hosted compiler was bootstrapped from a reference implementation written in C++. That C++ stage-0 compiler was retired in July 2026, once the seed became self-sufficient: its sources are frozen under retired/scalyc0/ as a historical reference, it has no build, and it cannot parse the current language. Today's build needs no C++ toolchain; C++ comes back only as a check on the seed.

    A compiler that compiles itself could carry something its sources do not say and hand it on through every seed — Ken Thompson's Reflections on Trusting Trust. So the repository also holds the compiler as C++, under trust/, written by the compiler's second back end (scalyc --emit-cpp) from the same plan the LLVM back end reads, and written again whenever the seed is. trust/check.sh builds a compiler from that C++ with a C++ compiler of your choice, lets it emit the seed, and compares the result with seed/ byte for byte; if they agree, the seed is what the sources say. This is David A. Wheeler's diverse double-compiling. The release workflow runs the check with GCC, in a container without clang, before it builds anything; trust/README.md says what the check proves and what stays trusted (the C++ compiler, libLLVM 21, the runtime's few C and assembly files, and the C++ itself).

    Hosts with a different data model (32-bit or big-endian) are not covered by the seed; supporting one would mean generalizing the compiler's size and alignment emission off its fixed 64-bit constants and minting a seed for that data model.
