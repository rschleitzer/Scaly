What runs here

    
One Scaly program, compiled to WebAssembly. Its work is a single for over the points of the
      picture. Nothing in it says “in parallel” or “on the graphics card”: the rounds of the loop do not depend
      on each other, so the runtime may hand them to other cores; and its body is arithmetic on 32-bit numbers,
      so the compiler also writes it as a kernel the card can run. What changes between the buttons is only what
      the host gives the program — one core, all of them, the card — and the picture comes out the same.
      relaxed before the loop allows the card's floating point, which rounds a little more loosely:
      on the card a few points in a thousand come out a shade different, and one on the very edge of the set
      may fall to the other side. The table says how many.

    
“Let Scaly decide” gives the program both: the runtime measures the first rounds on the processor and
      sends the loop to the card where that pays — a small picture with few iterations may stay on the cores.
      The times are those of the loop alone, measured by the program. The card needs its kernel compiled once —
      a browser translates it into the card's own language, and Safari takes far longer for that than for a
      run —, so the page does that in the background as soon as a program is loaded; where you are quicker, the
      table says how much of a time it was. The first run on the cores includes starting their threads.

  


  

    
The program — the original

    
    

      
      
      
    

    

    
Change it and build it: the Scaly compiler, built for WebAssembly, compiles your version here in
      the page — for threads and for the card, as the original was. The first build loads the compiler (about
      8 MB); after that a build takes a fraction of a second. The buttons above then run your version. It gets the
      same arguments — width, height, iterations, and the centre and width of the picture in billionths — and
      shows the picture it writes to a file whose name ends in .<width>x<height>.rgba;
      what it prints appears under the buttons.
